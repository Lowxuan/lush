# Lush 命令语言规范

版本 0.4.0 · 状态：M7 已实现，M8–M11 规划（0.3.7 已实现）

---

## 0. 摘要

Lush 是一门嵌入 C++ 宿主的命令语言，目标场景是 AutoCAD 式的「命令行 + GUI 深度融合」：

- 一条命令既可以一次写全参数直接执行，也可以在参数不足时进入会话，由命令行或鼠标逐个补齐；
- 语言本身支持变量、列表、Point、条件、循环、引用与函数调用，可编写脚本批量生成操作；
- 语言核心零宿主依赖：解析、求值、命令注册、会话管理都不认识 Qt 或绘图。

本规范只定义**语言与命令框架的契约**，不定义 C++ 头文件形状，也不涉及任何 GUI。

| D01 | 语句终止符 = 换行 / `;` / `}` / `else` / EOF；`\` 是唯一的显式续行 |
| D02 | Point 是独立类型，维度 2 或 3，坐标恒为 double |
| D03 | 下标从 0 开始 |

## 2. 词法

### 2.1 源文本

- 编码 UTF-8；允许开头有 U+FEFF BOM，BOM 被忽略。
- BOM 只允许出现在文件开头。BOM 不计入行/列：第一个非 BOM 字符位于 1:1；token 的 offset 仍是包含 BOM 的原始字节偏移。文件中其他位置的 U+FEFF 按非法字符报 L001。
- 换行支持 `\n`、`\r\n`、`\r`，统一视为一个换行。
- 源文本必须是合法 UTF-8，否则词法错误 L001。非法 UTF-8 按字节位置参与“首错”排序（见 10.3）。
- 标识符、关键字、运算符、标点均为 ASCII；字符串可含任意 Unicode。

### 2.2 空白与换行

水平空白：U+0020（空格）、U+0009（制表符）。

换行在词法阶段产生 `NL` token，但有两种抑制：

1. **括号抑制**：词法器维护 `(` 与 `[` 的嵌套深度（不区分两种括号）。深度 > 0 时不产生 `NL`。`{`、`}` 不计入深度。遇到没有对应开启的 `)` / `]` 时深度保持 0，不降到负数；括号匹配错误由语法层报告。
2. **续行抑制**：见 2.3。

`NL` 是否被解析器接受由语法位置决定（见 3.8）。

### 2.3 续行 `\`

在字符串与注释之外，遇到 `\` 时：

1. 向后跳过零个或多个水平空白；
2. 若紧接着一个换行，则把 `\`、这些水平空白、以及换行一起删除，**不产生 `NL` token**；
3. 若转到 EOF，报 L005（续行符位于 EOF）；
4. 否则报 L006（孤立的 `\`）。这里的“否则”包括 `\` 后接水平空白再接 `#` 注释，或接任何非换行字符。

`\` 之前的空白**不受影响**。因此：

```lush
a = 1 + \
2            # 拼成 a = 1 + 2
```

```lush
line f \
g            # 拼成 line f g，仍是两个参数
```

注意：`a\` 后接换行再接 `b` 会拼成标识符 `ab`。要保留分隔，写成 `a \`。

其他规则：

- 字符串里的 `\` 是转义符，不是续行；
- `#` 注释里的 `\` 是普通字符，注释到行尾结束，不续行；
- `\` 后只有水平空白直到 EOF → L005；
- `\` 后接非换行字符（包括 `#` 注释）→ L006；
- 被删除的换行**仍然递增物理行号**，诊断报告物理行/列；
- token 的 offset 始终指向原始源文本，便于行列映射。

### 2.4 注释

`#` 到行尾为注释。注释不产生 token。字符串里的 `#` 是普通字符。无块注释。注释不包含行尾换行；换行仍产生 `NL`（除非被 2.2 的规则抑制）。

### 2.5 标识符、关键字、大小写

标识符：

```
[A-Za-z_][A-Za-z0-9_]*
```

关键字（大小写不敏感）：

```
if  else  while  for  in  true  false  ref  break  continue  def  return
```

规则：

- 关键字：大小写不敏感（`IF`、`True` 均可）。
- 词法阶段保留标识符/关键字的原始拼写；关键字匹配与命令查找才做大小写不敏感比较。
- 命令/函数名：查找时大小写不敏感，但保留注册时的规范拼写用于显示。
- 变量名：大小写敏感。
- 变量名不得与已注册的命令/函数名（大小写不敏感比较）相同。作为**写入/绑定目标**的根名字时，报 S003；包括普通赋值（含 `int[0] = 1`、`int.x = 1`）、`++`/`--` 目标、`ref` 左值、`for` init 目标和 `for-in` 变量。
- 读取位置上的 callable 名（如 `int`、`len`）仍解析为 callable，不报 S003。因此 `int = ref x` 是 S003，而 `x = ref int` 在 RHS 查找时不是变量，报 R001；`x = int[0]` 是 R002（callable 不可索引），`x = *int` 是 R001（`int` 不是变量）。
- 关键字不是 `IDENT`；`true = 1`、`if = 1` 按语法错误（P001）处理，不是 S003。

### 2.6 数值字面量

整数：十进制 `[0-9]+`，类型 `int`，范围 `[-2^63, 2^63-1]`。

浮点数：必须小数点两侧都有数字，可选指数：

```
[0-9]+ "." [0-9]+ ( [eE] [+-]? [0-9]+ )?
[0-9]+ [eE] [+-]? [0-9]+
```

- `1.0`、`3.2343`、`1e3`、`1.0e-3` 合法；
- `1.`、`.5`、`1e`、`1e+`、`1.e3` 非法（L004）；
- 以数字开头的数值必须构成完整的整数或浮点数。紧跟数值的 ASCII 标识符字符、`_`、额外的 `.` 或非法指数属于非法数值延续，整个单元报 L004，不拆成“数字 + 标识符”；合法的 `e` / `E` 指数除外。例如 `123abc`、`1_000`、`0x10`、`1.foo`、`1..2` 都报 L004；
- 数值在分隔符处正常结束，分隔符不参与数值：水平空白、换行、`#`、`,`、`;`、`(`、`)`、`[`、`]`、`{`、`}`、`:`、`?` 以及运算符。`.` 与 `e` / `E` 是例外：紧跟数值时必须构成合法的小数/指数，否则 L004；
- 不支持十六进制、下划线分隔；出现即 L004；
- 浮点字面量必须是有限 double；上溢到 ±Inf 或下溢超出 double 可表示范围都报 L004（如 `1e309`、`1e-400`）；
- 字面量不带符号，负号是单目运算符；
- 十进制整数的**绝对值**必须 ≤ `2^63`；`> 2^63` 直接 L004。

**INT64_MIN 与 BoundaryInt**

int64 的正负范围不对称（`[-2^63, 2^63-1]`），而语言没有负数字面量，所以 `2^63` 这个"刚好越界"的字面量必须特殊处理：

1. 词法：绝对值等于 `2^63` 时产生一个 **`BoundaryInt` token**，不立即报错；
2. 语法：`BoundaryInt` 只有在**（可带括号的）单目 `-` 的直接操作数**位置合法；AST 保留为 `Unary(-, BoundaryInt)`，不替换成 `Int(INT64_MIN)`。`BoundaryInt` 是公开 AST 字面量节点，不携带值；
3. 其它任何位置 → L004，位置在 `BoundaryInt` token；
4. 求值：`Unary(-, BoundaryInt)` 产生 `INT64_MIN`，不触发溢出；对其它 int 的单目 `-` 仍做溢出检查。

```lush
-9223372036854775808      # Unary(-, BoundaryInt)，求值为 INT64_MIN
-(9223372036854775808)    # 同上，括号分组透明
-((9223372036854775808))  # 同上
 9223372036854775808      # L004
0 - 9223372036854775808   # L004（二元减法不折叠）
-9223372036854775808[0]   # L004（后缀使 BoundaryInt 不是直接操作数）
-9223372036854775809      # L004
--9223372036854775808     # 词法为 MinusMinus 前缀；S009 在 `--`
- -9223372036854775808    # 外层取负溢出 → R005
-(-9223372036854775808)   # 同上
-9223372036854775808 + 1  # 合法：INT64_MIN + 1
-9223372036854775808 - 1  # R005
```

命令参数按顶层空白切词，所以 `line - 922...` 会切成 `-` 与 `922...` 两个词并报 P004 在 `-`；`line (- 922...)` 在括号内不切词，是合法的 `Unary(-, BoundaryInt)`。

`9223372036854775808++` 是后缀 `++` 作用于 `BoundaryInt`，报 S009 在 `++`；`--9223372036854775808` 同理，S009 在 `--`。BoundaryInt 作为 `++`/`--` 的目标时先按目标不可赋值处理，不再报 L004。

### 2.7 字符串字面量

只使用双引号，单行。转义序列：

| 转义 | 含义 |
|---|---|
| `\\` | 反斜杠 |
| `\"` | 双引号 |
| `\n` | 换行 |
| `\r` | 回车 |
| `\t` | 制表符 |
| `\0` | NUL |
| `\uXXXX` | Unicode 码点（4 位十六进制；代理区非法） |

- 字符串在遇到换行或 EOF 前未闭合 → L002；
- 未知转义 → L003；
- 字符串内的 `\` 后紧跟换行 → L003（续行只发生在字符串外）；
- `\uXXXX` 必须恰好 4 位十六进制；非法十六进制数字报 L003，后面多余的十六进制字符按普通字符继续；
- 不合并 UTF-16 代理对：`\uD800`–`\uDFFF` 均报 L003，`\uD83D\uDE00` 也不例外；
- 字符串按 Unicode 码点处理：`len(s)` 返回码点数，`s[i]` 返回第 i 个码点组成的字符串。

### 2.8 运算符与标点

```
(  )  [  ]  {  }  ,  ;  :  ?  .  ->
=  ==  !=  <  <=  >  >=  +  -  *  /  %  !  &&  ||  ++  --
```

`->` 按最长匹配识别；它只用于用户函数返回类型，不是普通运算符。

`\` 只用于续行（2.3），不参与表达式。

词法器按最长匹配识别运算符和标点（如 `==` 优先于 `=`，`++` 优先于 `+`）。

### 2.9 词法错误

| 码 | 含义 |
|---|---|
| L001 | 非法字符 / 非法 UTF-8 |
| L002 | 字符串未闭合（含裸换行或 EOF） |
| L003 | 未知转义（含字符串内 `\` 后换行、非法 `\u`、代理区） |
| L004 | 数值字面量格式错误或越界（含浮点超出 double 范围） |
| L005 | 续行符后只有水平空白直到 EOF |
| L006 | 孤立的 `\`（后接非换行字符，包括 `#` 注释） |

## 3. 语法

### 3.1 程序、语句与终止

一个程序是语句序列。语句之间用以下之一分隔：

```
NL | ; | } | else | EOF
```

其中 `}`、`else`、EOF 是**隐式终止**（不消费成语句的一部分）；`NL` 与 `;` 由语句消费。连续的空行、多余 `;` 合法；空行不产生节点，`;` 按 3.2 产生 `EmptyStmt`。

顶层与块内都允许空行。控制语句（`if`/`while`/`for`/块）作为一个整体，同样要与下一条语句分隔；紧邻 `}` 或 EOF 时除外。

`}` 是隐式终止符：以块结束的控制语句不需要额外分隔符，例如 `if (a) {} b = 2`、`while (a) {} b = 2`、`{ a = 1 } b = 2` 都合法。`if (a) b = 1 c = 2` 中 `if` 以非块语句结束，`c` 不是合法分隔，报 P006 在 `c`。

### 3.2 语句形式

只有以下形式是语句：

1. 块：`{ stmt* }`
2. 条件：`if ( expr ) stmt [ else stmt ]`
3. 循环：`while ( expr ) stmt`
4. 循环：`for IDENT in expr stmt` 或 `for ( [IDENT = expr] ; [expr] ; [expr] ) stmt`
5. 跳转：`break` / `continue`
6. 赋值：`lvalue = expr`
7. 引用赋值：`IDENT = ref IDENT`
8. 命令：`IDENT word*`

**裸表达式不是语句。** 这是硬性规定，否则 `line` 单独一行会被解释成"读取变量 line"，永远无法进入交互命令。

语句位置只接受上面列出的形式。以 `(`、`[`、数字、字符串、`true`/`false`、`++`/`--` 等开头的输入一律在第一个 token 报 P001；因此单独的 `(1,2]`、`(1,2,3,4)`、`1++`、`(x)++` 都是 P001，而不是 P003/P005/S009。P003/P005 只在表达式位置（赋值 RHS、命令参数、括号内、调用参数、条件、for 头等）报告。

空语句 `;` 合法，也可以作为控制语句的 body，例如 `if (a);`、`while (a);`、`for (;;);`、`if (a); else b = 2`。在 `if (a); b = 2` 中，`;` 既是空 body，也终止该 `if` 语句，`b = 2` 是下一条语句。

`EmptyStmt` 节点的产生规则：

- 出现在语句位置的 `;` 产生 `EmptyStmt`；连续 `;;` 的每个分号都产生一个 `EmptyStmt`（除非它已被前一条非空语句消费为终止符）。
- 作为控制语句 body 的 `;` 产生 `EmptyStmt`。
- 仅作为非空语句终止符的 `;` 不产生节点，例如 `a = 1;`。
- `{};` 中 `;` 是 `EmptyStmt`；`if (a) {}; else b = 2` 中该 `;` 也是 `EmptyStmt`，因此 `else` 不再绑定到该 `if`（见 6.2）。
- 语句的 Span 不包含末尾终止符；`EmptyStmt` 自己的 Span 包含它的 `;`。

### 3.3 表达式与优先级

从低到高：

| 级别 | 运算符 | 结合性 |
|---|---|---|
| 1 | `?:` | 右结合 |
| 2 | `\|\|` | 左结合 |
| 3 | `&&` | 左结合 |
| 4 | `==` `!=` | 左结合 |
| 5 | `<` `<=` `>` `>=` | 左结合 |
| 6 | `+` `-` | 左结合 |
| 7 | `*` `/` `%` | 左结合 |
| 8 | 前缀 `-` `!` `*` `++` `--` | 右结合 |
| 9 | 后缀 `[expr]` `.IDENT` `(args)` `++` `--` | 左结合 |
| 10 | 原子 | — |

- `*` 在第 7 级是乘法，在第 8 级是解引用；由位置区分。
- 解引用的操作数只能是变量名，且 `*` 必须紧贴变量：`*h` 合法；`* h` 是 P001（在 `h`）；`*1`、`*(h)` 也是 P001。解引用后不能接任何后缀：`*h[0]`、`*h.x`、`*h(1)`、`*h++` 都是 P001（在对应后缀）。
- `*h` 作为右值等价于读取 `h`；`*h = v` 是整值写穿透。二者都合法。
- 在表达式位置，前缀 `-`、`!`、`++`、`--` 不要求紧贴操作数；`*` 是唯一要求紧贴的前缀运算符（因为它同时是解引用）。
- `++` / `--` 的操作数必须是可赋值目标；否则报 S009，位置在运算符 `++`/`--`。`Deref` 不算可赋值形状。括号分组对可赋值性透明：`(x)++` 合法，等价于 `x++`；`(*h)++` 的目标是 Deref，报 S009，而 `*h++` 是 P001（后缀不能直接接在解引用之后）。
- 成员后缀 `.` 必须紧贴，且后面必须是 `IDENT`。紧贴 `.` 后不是 `IDENT` 时报 P004 在 `.`（成员名位置不按 `ref`/`def`/`return` 关键字处理）；如果 `.` 后直接是语句终止符或 EOF，则报 P002 在该终止符/EOF。带空白时 `p .x` 不构成后缀，按当前上下文报 P001/P004。
- 赋值不是表达式：`a = b = c` 在第二个 `=` 处报 P001。
- 三元只求值被选中的分支。
- **所有后缀运算符必须紧贴左操作数**：`a[0]`、`p.x`、`f(x)`、`i++` 合法；`a [0]`、`p .x`、`f (x)`、`i ++` 都不构成后缀运算。`i ++` 在表达式位置是 P001（在 `++`）。
- **调用是后缀**：任意表达式紧贴 `(` 即可调用；callee 必须是 callable，否则 R012。

原子：

- `INT`、`FLOAT`、`STRING`、`true`、`false`
- `IDENT`：变量；若该名字是已注册的函数/类型构造器，则是 callable 值；若是命令名 → S008
- `( expr )`：分组
- `( expr , expr [ , expr ] )`：Point 字面量（2 或 3 个坐标）
- `[ [expr {, expr}] ]`：list 字面量

调用括号与 Point 括号的区分：

> **调用是后缀：callee 紧贴 `(`。调用括号内，顶层逗号是参数分隔符；其他位置的 `(a,b)` 是 Point。**
> `f(1,2)` 是 2 个参数；`f((1,2))` 是 1 个 Point 参数；`type(4.4)(2)` 先取 `double` 再调用它。

### 3.4 命令参数：切词规则

命令语句的形式是：

```
IDENT word*
```

名称之后、直到语句终止符为止的 token，按**顶层空白**切分成词：

- 顶层 = `(` 与 `[` 的嵌套深度为 0；
- 一个新词开始于：第一个 token，或任意一个 `wsBefore == true` 且深度为 0 的 token；
- 括号内部（深度 > 0）的空白不切词；
- 每个词必须被完整解析为 `barePoint` 或 `expr`，不允许残留 token。

`wsBefore` 的精确定义：在经过 2.3 的续行删除后的逻辑文本中，从当前 token 的起点向左看，紧邻的字符是空格或 tab 时为 `true`，否则为 `false`。行首缩进因此计入；换行本身不是水平空白，换行后没有缩进则为 `false`；文件第一个 token 若无前导空白为 `false`。注释字符不是空白，但注释前后的空格/tab 按普通字符处理。`NL` 与 EOF 的 `wsBefore` 固定为 `false`。

因此 `a \` 换行 `b` 中 `a` 后的空格保留，`b.wsBefore == true`；`a\` 换行 `b` 拼成标识符 `ab`，不产生两个 token。

推论：

- `line f g` → 两个词 `f`、`g`；
- `line 0,0 1,1` → 两个词；
- `line (0, 0) (1, 1)` → 两个词（括号内空格不切）；
- `line a+b c` → 两个词；
- `line a - b` → 三个词 `a`、`-`、`b`，`-` 无法构成表达式 → 语法错误 P004 在 `-`；
- 在参数顶层，一元运算符必须紧贴操作数（这是切词规则；表达式位置的前缀可留空白），所以 `line -1 -2` 是 `-1` 与 `-2` 两个词；括号内允许 `(- 1)`；
- 调用必须紧贴：`f(x)`、`type(1)(2)`；`f (x)` 在参数位置是两个词，在表达式位置是语法错误；
- `line *h` → 一个词（解引用）；`line * h` → 两个词，第一个词是 `*`，无法构成表达式 → P004 在 `*`；
- `line 1,2,3,4` → 裸坐标最多 3 个，P004 在词首 token `1`；`line (1,2,3,4)` → P003 在 `(`；`line (1,2),3` → 坐标不能是 Point 字面量，P004 在 `(`；
- 参数里的复杂表达式请整体加括号，括号内空白随意：`line (a + b, c) (d, e)`。

**命令词的错误位置**

命令词解析失败时按下列顺序确定错误：

1. 具体结构错误优先保留自己的码和位置：P003（Point 元素个数）、P005（括号不匹配）、P001（括号内的尾随/多余逗号、残留闭括号）、P002（缺少表达式且已到语句终止符/EOF）、S004、S009、L004。
2. barePoint 的某个坐标本身是非 bare 的 Point 字面量 → P004 在该坐标起点，例如 `line 1,(2,3)` → P004 在 `(2,3)` 的 `(`。
3. 其它无法整词解析的情况 → P004 在该词的第一个 token，例如 `line 1,2,3,4` → `1`，`line a+ b` → `a`。
4. 词在语句终止符/EOF 上结束且只是缺少表达式/操作数 → P002（见 3.9）；词在空白处结束时仍是 P004。若词首根本无法开始表达式（如 `+`），或 barePoint 已出现逗号但坐标不完整，即使到 EOF 也仍是 P004。

barePoint 的规则：一旦已经出现逗号但后续坐标不完整，就视为非法词，P004 在词首 token，不按“还可以继续追加”处理。例如 `line 1,`、`line 1,2,`、`line 1,2,3,` 都是 P004 在 `1`。

缺少操作数的命令词内部错误按“包含它的表达式起点”报 P004：

- `line (a + )` → P004 在 `(`；
- `line f(a + )` → P004 在 `f`；
- `line [1 + ]` → P004 在 `[`；
- `line (1 ? 2 : )` → P004 在 `(`。

尾随逗号不是“缺少操作数”：

- `line f(1,)` → P001 在 `)`；
- `line [1,]` → P001 在 `]`；
- `line (1,)`、`line (1,2,)`、`line (1,2,3,)` → P001 在 `)`。

残留闭括号：

- `line 1,2)` → P001 在 `)`；
- `line 1,2]` → P001 在 `]`；
- `line (1,2)` 后多一个 `)` → P001 在第二个 `)`。

**注意**：命令名与第一个词可以紧邻，`line(1,2)` 等价于 `line (1,2)`：语句位置没有调用语法，`(` 只是第一个词的开始。

### 3.5 裸坐标糖

仅在命令参数位置，一个词可以整体解析为裸 Point：

```
barePoint = simple ( "," simple ){1,2}
simple    = "-"? atom suffix*
atom      = INT | FLOAT | IDENT | "(" expr ")"
suffix    = "[" expr "]" | "." IDENT | "(" [args] ")"
```

后缀同样必须紧贴：`f(1,2),3` 是一个裸坐标（第一维是调用结果），`f (1,2),3` 会被空白切词。

- 坐标个数必须是 2 或 3；多出的坐标是非法词，P004 在词首 token（`line 1,2,3,4` → `1`）；
- 逗号两侧不能有空白（空白会先切词）；
- 每个坐标必须是 int 或 double，转换时统一变为 double；
- 坐标本身不能是 Point 字面量：`(1,2),3` 是 P004 在 `(`；`line 1,(2,3)` 是 P004 在第二个坐标的 `(`；被分组括号包住也算，例如 `line ((1,2)),3`、`line 1,((2,3))` 都是 P004 在坐标起点；
- 已经出现逗号但后续坐标不完整时，P004 在词首 token，不按“可继续追加”处理：`line 1,`、`line 1,2,`、`line 1,2,3,` 都是 P004 在 `1`；
- 多余坐标优先于“坐标是 Point 字面量”：`line 1,2,3,(4,5)` 是 P004 在 `1`；
- `1,2`、`-1,-1`、`p.x,p.y`、`(a+1),b` 合法；
- `1, 2` 会切成 `1,` 与 `2`，`1,` 非法 → P004 在 `1`；`1 ,2` 的第二个词是 `,2` → P004 在 `,`。

裸坐标与括号 Point 等价：`line 1,2 3,4` ≡ `line (1,2) (3,4)` ≡ `line (1, 2) (3, 4)`。

注意：任何命令参数位置都会**优先尝试**裸坐标，因此 `move 1,2` 是一个 Point 而不是两个数值；需要两个数值参数时写 `move 1 2`。

### 3.6 Point 与 list 字面量

| 写法 | 类型 |
|---|---|
| `(1,2)` | Point2 |
| `(1,2,3)` | Point3 |
| `(1)` | 分组，值为 int 1 |
| `(1,2,3,4)` | 语法错误 P003（提示改用 `[1,2,3,4]`） |
| `[]` | 空 list |
| `[1,"a",(2,3)]` | 异构 list |

- Point 坐标必须是 int/double，构造时统一为 double；坐标不是数值 → R006；
- list 元素类型不限；
- 两个字面量都不允许尾随逗号；尾随逗号是 P001，位置在对应的 `)` 或 `]`：`(1,)`、`(1,2,)`、`(1,2,3,)` 都是 P001 在 `)`，`[1,]` 是 P001 在 `]`；
- `(a,b)` 中的 `a`、`b` 可以是任意表达式（含空格），因为括号抑制换行且不切词。

### 3.7 语句 / 表达式判定

解析器在**语句位置**按以下确定性过程判定：

1. `{` → 块。
2. 关键字 `if` / `while` / `for` / `break` / `continue` / `def` / `return` → 对应语句；`def` 只在顶层合法，`return` 只在函数体内合法。
3. `*` → 赋值语句，解析紧贴的 `*IDENT`，随后必须是 `=`；不是 `=` 时按 P001/P002 报告。
4. `IDENT`：
   1. 尝试解析**连续的**可赋值路径：`IDENT` 后紧跟（无空白）`[...]` 或 `.IDENT`；
   2. 若路径之后是 `=` → 赋值语句；若 RHS 是 `ref IDENT` → 引用赋值；
   3. 否则回退到路径起点之后，按命令语句解析：`IDENT` 是命令名，其余按切词规则成为参数。

在**表达式位置**：

- 任意表达式后紧跟 `(` → 调用；callee 必须是 callable（否则 R012）；
- `IDENT` → 变量；若该名字是内建/注册函数、类型构造器或用户函数，则是 callable 值；若是命令名 → S008；
- `(` → Point 或分组（看顶层逗号个数）；
- `[` → list；
- 紧贴的 `.` 后必须是 `IDENT`，否则按 3.3 的成员规则报 P004 在 `.`（`.` 后直接是终止符/EOF 则 P002）。成员名位置不把 `ref`/`def`/`return` 当作关键字形式处理：`a = x.ref`、`a = x.def` 都是 P004 在 `.`。

调用可以链式：`type(4.4)(2)` 解析为 `(type(4.4))(2)`；中间有空白则不是调用（`type(4.4) (2)` → P001）。

路径必须"连续"这一条很重要：`p.x = 5` 是赋值，`p .x = 5` 不是（第二个 token 有前导空白，路径在 `p` 处结束，随后不是 `=`，于是按命令解析并报错）。

**语句位置的补充例子**

- `f(1,2)` 在语句位置是命令 `f` + 一个 Point 参数，不是函数调用；`f()` 是命令 `f` + 空括号词，`()` 不是合法表达式 → P004 在 `(`。
- `x[0]` 单独一行不是赋值，回退为命令 `x` + 参数 `[0]`；语法合法，未知命令留给 S001。
- `x.y` 单独一行回退为命令 `x` + 词 `.y` → P004 在 `.y` 的 `.`。
- `p .x = 5` 回退为命令 `p`，词 `.x`、`=`、`5` → P004 在 `.x`。
- `a [0] = 1` 回退为命令 `a`，词 `[0]`、`=`、`1` → P004 在 `=`。
- `x++` 单独一行回退为命令 `x` + 词 `++` → P004 在 `++`；`x + 1` → P004 在 `+`；`x == 1` → P004 在 `==`。
- `*h = v` 是引用写穿透赋值；`* h = v` 是 P001（在 `h`）；`*h[0]`、`*h++`、`*h.x`、`*h(1)` 都是 P001（在对应后缀）。
- `a = ref` 单独出现，或 `a = ref` 后用**普通换行**接变量，都是 S004（在 `ref`）；只有显式 `\` 续行才允许 `ref` 与变量拼到同一逻辑行。Repl 中输入以 `a = ref \` 结尾时等待下一行。
- `ref` 出现在其它位置、`ref` 右侧不是简单变量名、`ref` 左侧不是简单变量名，均报 S004（位置在 `ref`）。
- `return` 出现在函数外 → S010（在关键字）；`def` 出现在非顶层 → S011；但紧贴 `.` 后的成员名位置例外，按成员规则报 P004 在 `.`。
- `a = x.ref`、`a = x.def` → P004 在 `.`；`a = x .ref` 中 `.` 有前导空白，不构成成员后缀 → P001 在 `.`。
- `a = b = c` → P001 在第二个 `=`。
- `a = 1 b = 2` → P006 在 `b`；`a = 1 2` → P001 在 `2`。

### 3.8 换行可省略的位置

解析器在以下位置跳过 `NL`：

- 程序开头、语句之间、块内空行；
- `{` 之后、`}` 之前；
- `if (...)` / `while (...)` / `for (...)` 的 `)` 之后；
- `for IDENT in expr` 的 `expr` 之后；
- `else` 之前与之后。

因此以下都合法：

```lush
if (a)
{
    ...
}
else
{
    ...
}
```

```lush
if (a)
line 0,0 1,1
```

块内语句仍然需要 `NL` 或 `;` 分隔（紧邻 `}` 的语句除外）。

### 3.9 语法错误

| 码 | 含义 |
|---|---|
| P001 | 意外的 token |
| P002 | 意外结束（EOF，或语句层终止符处缺少表达式） |
| P003 | Point 字面量元素个数不是 2 或 3 |
| P004 | 命令参数不是合法表达式 |
| P005 | 括号不匹配 |
| P006 | 语句缺少终止符 |

未闭合的 `{`/`(`/`[` 在脚本 EOF 上归入 P002；REPL 将其视为 `Incomplete`（见 10.2）。

**位置与判定**

- P001：意外 token 的起点。语句位置以 `(`、`[`、字面量、`++`/`--` 等开头也报 P001 在第一个 token；因此单独的 `(1,2]`、`(1,2,3,4)`、`1++`、`(x)++` 都是 P001，P003/P005/S009 只在表达式位置报告。
- P002：EOF 位置，或语句层终止符（`NL`、`;`、`}`、`else`）的起点，零长度 span；help 说明缺少什么。在 `(`/`[` 内部，`;`/`}` 不是语句终止符，遇到它们是 P001。
- P003：Point 字面量的开头 `(`。
- P004：默认在出问题的命令词第一个 token；如果 barePoint 的某个坐标本身是非 bare 的 Point 字面量，则在该坐标起点；具体结构错误（P003/P005/P001 括号内尾随/多余逗号/P002/S004/S009/L004）保留自己的码和位置。词在语句终止符/EOF 上结束且只是缺少表达式/操作数时报 P002，不报 P004；词首根本无法开始表达式或 barePoint 逗号后坐标不完整时仍为 P004。
- P005：在期待闭括号时遇到不匹配的闭括号，位置在该闭括号；没有 opener 的孤立 `)` / `]` / `}` 是 P001。
- P006：语句已经完整，但没有 `NL` / `;` 分隔，且下一个 token 能开始新语句（`IDENT`、`{`、`*`、`if`/`while`/`for`/`break`/`continue`/`def`/`return`）；位置在该 token。其它意外 token 按 P001。`return` 在函数外的语义错误按 S010 处理；`ref` 按 S004 处理。

例子：

- `a = 1 b = 2` → P006 在 `b`；
- `a = 1 2` → P001 在 `2`（`2` 不能开始语句）；
- `a = b = c` → P001 在第二个 `=`；
- 表达式位置 `a = (1,2]` → P005 在 `]`；单独的 `(1,2]` → P001 在 `(`；
- 表达式位置 `a = (1,2,3,4)` → P003 在 `(`；单独的 `(1,2,3,4)` → P001 在 `(`；
- `line a - b` → P004 在 `-`；
- `line 1, 2` → P004 在 `1`；
- `line 1,(2,3)` → P004 在 `(2,3)` 的 `(`；
- `line 1,2,3,4` → P004 在 `1`；
- `line a+ b` → P004 在 `a`；`line a+` 到 EOF → P002 在 EOF；
- `line 1?2` 到 EOF → P002 在 EOF；`line 1?2 3` → P004 在 `1`；
- `a =` 后接 NL → P002 在 NL 起点；`a = ;` → P002 在 `;` 起点；
- `a = (1;)` → P001 在 `;`（括号内不是语句终止符）；
- `line 1,2)` → P001 在 `)`；
- `line (1,2]` → P005 在 `]`；
- `line (a + )` → P004 在 `(`；`line f(1,)` → P001 在 `)`；`line [1,]` → P001 在 `]`；
- `line (1,)`、`line (1,2,)`、`line (1,2,3,)` → P001 在 `)`；
- `line 1,2,3,` → P004 在 `1`；
- `line 1,,2` → P004 在 `1`（barePoint 内多余逗号）；`line (1,,2)` → P001 在第二个 `,`（Point 字面量内部）。

空语句 `;` 是合法终止符，也可以作为控制语句的 body；它不会触发 P006。

### 3.10 用户函数定义与类型注解

```text
defStmt     = "def" IDENT "(" [ param { "," param } ] ")"
              [ "->" type ] body ;
param       = IDENT [ ":" type ] ;
body        = block | stmt ;              (* 单条语句或 block *)
type        = "int" | "double" | "bool" | "string" | "list"
            | "point" | "point2" | "point3" | "any" | "callable"
            | "void" ;
returnStmt  = "return" [ expr ] ;
```

- `def` 只允许出现在程序顶层；出现在 block、`if`、循环或另一个函数体内是 S011。
- 参数注解省略时等价于 `any`。参数不支持默认值、可选参数或变参；参数名必须唯一。
- `void` 只允许作为返回类型；不能出现在参数注解中。
- 没有 `->` 的函数是 void 函数；有 `->` 的函数是值函数。
- 顶层 `def` 在执行前统一收集并提升：同一程序内的函数可以在定义之前调用，可以互相递归；同一脚本重复定义同名函数报 S011。REPL 中重新定义同名用户函数允许替换。
- 函数名进入 common callable namespace，大小写不敏感；不能与关键字、内建函数、参考宿主命令或已注册 callable 冲突。用户函数名冲突是 S011，变量名与 callable 冲突仍按 S003。
- 函数值是一等 callable，可存入变量/list、作为参数传递、作为返回值；`type(f)` 返回 `type`，`string(f)` 输出函数名。
- 函数体是新的局部作用域；参数在该作用域内绑定。函数体可以看到当前全局环境，但不捕获定义点的局部变量；v1 不支持闭包。
- 函数体内的赋值沿用 §6.1：找到最近可见绑定就写入该绑定，找不到才在当前函数作用域创建。因此函数可以修改已存在的全局变量；不会隐式创建同名局部变量。
- 语句位置调用使用 `f 1 2`；表达式位置调用使用 `f(1, 2)`。语句位置的 `f(1, 2)` 仍按命令 + 一个 Point 参数解析，不是函数调用。
- 用户函数的参数和返回类型注解是运行时契约，不会被静默转换成其它类型；只允许 `double` 参数接收 int 并提升，以及 `-> double` 返回值把 int 提升为 double。用户函数参数不接受 list → point 隐式转换，必须显式 `point(list)`。
- `return expr` 只能出现在值函数中；`return;` 只能出现在 void 函数中；`return` 出现在函数外是 S010。
- 值函数执行到函数体末尾且没有执行到 `return expr` → R014。递归深度超过 1024 → R015。

## 4. 类型与值

### 4.1 类型

| 类型 | 说明 |
|---|---|
| `int` | 有符号 64 位整数 |
| `double` | IEEE-754 双精度；不接受 NaN / ±Inf |
| `bool` | `true` / `false` |
| `string` | UTF-8 字符串，按码点索引 |
| `list` | 异构、可变、值语义 |
| `point` | 2 或 3 维，坐标恒为 double |
| `type` | 可调用值（函数/类型构造器）的类型；`type` 本身也是 callable |

`ref` 不是一等类型：它只能作为变量的当前内容存在，不能进入 list、Point、命令参数或返回值（见 4.5）。

`void` 只描述"没有返回值"，不是值。

`type` 既是可调用值的类型名，也是一个内建 callable（返回参数的类型构造器）。`int`、`double`、`bool`、`string`、`list`、`point`、`type`、`len` 都是 callable 值；其中前六个是数据类型的构造器，`type` 是元类型兼查询函数，`len` 是普通函数。用户 `def` 定义的函数也是 callable 值。callable 值可以存入变量/list、作为 `ref` 目标、作为命令的 `any` 参数，但不能参与算术或大小比较（见 4.7）。

用户函数的类型注解使用 `callable` 表示 callable 值，等价于值类型 `type`。void 函数没有值形态，只能作为语句调用；把 void 函数调用放到表达式位置是 S012。

### 4.2 Point

- 维度在创建时固定为 2 或 3；`len(p)` 返回维度。
- `p.x` / `p.y` / `p.z` 是 `p[0]` / `p[1]` / `p[2]` 的糖；2 维点访问 `.z` 或 `p[2]` 报 R003。
- 分量可写：`p[0] = 1`、`p.y = 2`，写入的 int 会转成 double。
- 成员只读：`p.length` 不存在（用 `len(p)`）。

### 4.3 list

- 异构：`[1, "a", (2,3), [4]]` 合法。
- 可变：`a[0] = 1`、`a[1][0] = 9`。
- 派生成员：`a.length`（只读，等价于 `len(a)`）。
- 没有切片、没有 `+` 拼接、没有内建排序（v1）。

### 4.4 值语义与拷贝

**读取任何表达式都得到一个独立的值。** 具体地：

- 读取变量：拷贝其值（深拷贝）；
- 读取 `a[i]`：拷贝该元素；
- 赋值、命令/函数参数绑定、list/Point 字面量构造：都发生拷贝；
- 因此 `h = f` 之后修改 `h` 不影响 `f`；嵌套 list 同样独立；
- callable 值（类型为 `type`）不可变，拷贝等价于复制引用（身份不变）。

`ref` 是唯一的别名机制。

> 性能说明：v1 采用朴素深拷贝；大列表在热循环里请用 `ref`。未来可在不改语义的前提下引入 COW。

### 4.5 ref

语法上只有一种引用赋值：

```lush
h = ref f
```

约束：

1. 左侧必须是**简单变量名**；`a[0] = ref f`、`p.x = ref f` 非法（S004）。
2. 右侧必须是简单变量名；`ref 1`、`ref f[0]` 非法（S004）；名字未绑定 → R001。
3. 若右侧变量当前已经持有引用 → R008（不允许引用的引用）。
4. 引用指向**变量的单元（cell）**，不是指向值。变量后来被重新赋值，引用看到新值。
5. 左侧的名字按 6.1 的目标解析规则处理：写入最近的同名绑定，不存在则在当前作用域创建。
6. 每个 Cell 带 `hasInboundRef` 标记。`h = ref f` 成功后，`f` 的 cell 被标记为 true。
7. 若某 cell 的 `hasInboundRef == true`，它不能再被改绑为引用：`f = ref g` → R008；普通赋值 `f = v` 仍然允许，`h` 会看到新值。
8. 自引用：`h` 已绑定时执行 `h = ref h` → R008。
9. 引用赋值先校验右侧，再解析/创建左侧；因此 `h = ref h` 在 `h` 未绑定时是 R001，已绑定时是 R008。§6.1 的普通赋值 target-first **不适用于** `ref` 赋值。
10. 因为上述规则，引用最多一层；读取时只需跟随一次，不需要递归或环检测。
11. `ref` 与右侧变量必须在同一逻辑行。普通换行是语句终止符：`a = ref` 单独出现，或 `a = ref` 后用普通换行接变量，都报 S004（位置在 `ref`）；显式 `\` 续行可以把两行拼成同一逻辑行。Repl 中输入以 `a = ref \` 结尾时返回 `Incomplete(TrailingContinuation)`；脚本模式没有续行时仍是 S004。
12. `ref` 出现在其它位置、右侧不是简单变量名（如 `ref 1`、`ref f[0]`、`ref f + 1`、`a = ref 1`），或左侧不是简单变量名（如 `a[0] = ref f`、`p.x = ref f`、`*h = ref f`），均报 S004（位置在 `ref`）。已经出现非简单 RHS 时，即使末尾有续行也报 S004，不转 `Incomplete`。
13. `*` 必须紧贴变量：`*h` 合法（右值等价于读 `h`，`*h = v` 是写穿透）；`* h` 是 P001（在 `h`）；`*h[0]`、`*h.x`、`*h(1)`、`*h++` 都是 P001（在对应后缀）。
14. 紧贴 `.` 后的成员名位置不按 `ref`/`def`/`return` 关键字处理；`x.ref`、`x.def` 按成员语法错误报 P004 在 `.`。

解析器在看到 `=` 后紧跟关键字 `ref` 时进入引用赋值形式；`ref` 出现在其它位置 → S004。

语义表：

| 写法 | 行为 |
|---|---|
| `h = ref f` | 让 `h` 成为 `f` 的别名 |
| 读 `h` | 解引用后拷贝值 |
| `h[i] = v` | 通过引用写 `f` 的元素 |
| `h.m = v` | 通过引用写 `f` 的成员 |
| `h++` / `h--` | 通过引用读改写 |
| `*h = v` | 用 `v` 整体替换 `f` 的值 |
| `h = v` | **重绑定** `h` 为普通值，`f` 不变 |
| `h = ref g` | 重绑定 `h` 到 `g`；若 `h` 已被其它引用指向 → R008 |
| `*h`（右值） | 等价于读 `h` |

其他规则：

- 引用不是一等值：`echo h`、`h + 1`、`f(h)`、`[h]` 都先解引用；
- `type(h)` 返回被引用值的类型构造器，永远不返回 `ref`；
- 引用持有 cell 的所有权，因此局部变量离开作用域不会悬空；
- `for i in` 每轮创建**新 cell**，引用可安全逃逸到循环外；
- C 风格 `for(i=...)` 的 `i` 在整个循环期间是**同一个 cell**，引用会看到最终值。
- `hasInboundRef` 不会被清除：v1 保守地认为"曾经被引用过"的 cell 不能再改绑为引用，即使引用已经离开作用域。

### 4.6 隐式转换

只允许两种隐式转换：

1. `int → double`：混合数值运算、写入 Point 分量、绑定 `number` 参数、`point(...)` 构造。
2. `list → point`：仅发生在**期望 Point 的位置**（命令/函数参数声明为 `point`，或 `point(v)` 的单参数形式）。要求长度 2 或 3，且每个元素是 int/double；全部转成 double，否则 R006。

不存在 `bool ↔ int`、`string ↔ number`、`point ↔ list`（后者只能显式 `point(v)` 或参数绑定）。callable 不参与任何隐式转换。

赋值不转换：`p = [1,2]` 之后 `p` 仍是 list。

### 4.7 相等与排序

`==` / `!=`：

- 数值之间先提升到 double 比较（`1 == 1.0` 为 true）；超过 2^53 的 int 与 double 混合比较可能丢精度，这是已知限制；两个 int 之间按整数精确比较；
- bool 只能与 bool；
- string 按码点逐位比较；
- Point 要求同维度，逐坐标比较；
- list 要求同长度，逐元素递归比较；
- callable 按**身份**比较：`type(4.4) == double` 为 true，`type(1) == double` 为 false；
- 其它跨类型比较 → R002。

`<` `<=` `>` `>=`：

- 数值之间；
- string 之间按码点字典序；
- bool、list、Point、callable → R002。

### 4.8 真值

**条件必须是 bool。** `if (1)`、`while ("x")` 一律 R002。`&&` / `||` / `!` 的**被求值**操作数也必须是 bool；`&&`/`||` 短路时不求值右侧，因此不检查右侧类型。

## 5. 运算语义

### 5.1 算术

| 运算 | 允许的类型 | 结果 |
|---|---|---|
| `a + b` | int/int, 任一 double | 数值，提升到 double |
| `a + b` | string/string | 拼接 |
| `a + b` | point/point（同维） | 逐坐标相加 |
| `a - b` | 数值 | 数值 |
| `a - b` | point/point（同维） | 逐坐标相减 |
| `-a` | 数值 | 数值 |
| `-a` | point | 逐坐标取反 |
| `a * b` | 数值 | 数值 |
| `a * b` | point × 数值，数值 × point | 逐坐标缩放 |
| `a / b` | 数值 | 数值 |
| `a / b` | point / 数值 | 逐坐标缩放 |
| `a % b` | int/int | 截断余数，符号随被除数 |
| `++` / `--` | int 可赋值目标 | 前缀返回新值，后缀返回旧值 |

不允许：point 与标量相加、point 乘 point、point 取模、list 参与任何算术、callable 参与任何算术或大小比较（只允许 `==`/`!=`）。

整数除法向零截断：`-3/2 == -1`。任何除零（含 `0.0`）→ R004。

### 5.2 逻辑与比较

- `&&` / `||`：bool × bool → bool，短路求值；
- `!`：bool → bool；
- 比较结果恒为 bool。

### 5.3 索引与成员

| 接收者 | 索引/成员 | 结果 | 可写 |
|---|---|---|---|
| `list` | `[int]` | 元素（拷贝） | 是 |
| `string` | `[int]` | 单码点字符串 | 否 |
| `point` | `[0/1/2]` | double | 是 |
| `point` | `.x` / `.y` / `.z` | double | 是（`.z` 仅 3 维） |
| `list` / `string` | `.length` | int | 否 |
| 其它 | 任意 | R002 | — |

索引必须是 int（double 不隐式转 int）。负索引与越界 → R003。对只读位置（string 元素、`.length`）赋值 → R002。

### 5.4 自增自减

- 目标必须是可赋值形状：变量、元素、成员（经引用时写穿透）；字面量、调用、二元/三元表达式、Deref 等不是可赋值目标 → S009（位置在 `++`/`--` 运算符）。
- 括号分组对可赋值性透明：`(x)++` 合法，等价于 `x++`。
- 目标类型不是 int → R002；溢出 → R005。
- 后缀 `++`/`--` 在普通表达式中立即写回；只有作为赋值目标路径的一部分时延迟提交（见 §6.1）。前缀始终立即写回。
- `++` 可以出现在表达式中：`x = i++`。

### 5.5 三元

`cond ? a : b`：`cond` 必须是 bool；只求值被选中的分支；两个分支类型不必相同。

### 5.6 溢出与浮点

- int 的 `+ - * / %`、单目 `-`、`++ --` 全部做溢出检查，越界 → R005；
- `INT64_MIN / -1` → R005；`INT64_MIN % -1` 定义为 0（余数可表示），不报 R005；
- double 运算产生 NaN 或 ±Inf → R009；
- 不支持 NaN 字面量或比较。

### 5.7 求值顺序

子表达式默认从左到右；语句与特殊形式按以下规则：

- 二元运算先左后右；`Call` 先 callee 再参数；`Index` 先 receiver 再 index；`Member` 先 receiver；Point/list 字面量元素从左到右。
- `&&` / `||` 短路；三元先求 `cond`，再只求选中分支。
- 普通赋值先求目标路径，再求 RHS，再写入，最后提交目标路径中的后缀；见 §6.1。
- `ref` 赋值先求 RHS，再解析/创建 LHS；见 §4.5。
- `for` init 先在外层求 RHS，再新建循环变量；见 §6.4。
- 命令参数从左到右求值；见 §3.4。

## 6. 语句语义

### 6.1 赋值与作用域

- 变量无需声明，首次赋值即在**当前作用域**创建。
- 赋值目标解析顺序：从内到外查找最近的同名绑定；找到则写入该绑定，找不到则在当前作用域创建。查找发生在目标求值阶段；简单变量目标的创建发生在写入阶段（见下）。
- “写入绑定”指替换该绑定**自身**的值：即使它当前持有引用，`h = v` 也只改变 `h`，不写穿到 `h` 指向的目标；要写穿请用 `*h = v`、`h[i] = v` 或 `h.m = v`。
- 因此内层块里 `x = 2` 会更新外层可见的 `x`，而不是新建局部变量。
- 唯一能"遮蔽"的情况是 `for` 的循环变量（它在 for 作用域新建绑定）。
- 作用域：
  - 程序 = 全局作用域；
  - 每个 `{}` 块在每次进入时创建新作用域；
  - `for` 创建一个作用域容纳循环变量与循环体；
  - 无花括号的语句体不创建新作用域（共享外层，循环变量除外）。
- 块结束时移除该层名字绑定；被引用持有的 cell 继续存活。

**普通赋值的目标优先与后缀延迟**

- 普通 `=` 先求目标路径，再求 RHS。目标求值包括根变量、索引和成员路径；索引/成员子表达式按从左到右求值。
- 目标路径中的后缀 `++`/`--` 返回旧值，并把 `+1`/`-1` 登记到待提交队列，不立即写回。登记时检查 `old ± 1` 的溢出（R005 在运算符）。
- RHS 求值完成后，先执行赋值写入，再按登记顺序提交队列。RHS 中的后缀仍立即写回；目标路径中的前缀仍立即写回。
- 多个目标后缀可以指向同一 cell；它们都读旧值，提交时按登记顺序应用 delta。提交时若当前值加 delta 溢出，且此前没有错误，报 R005。
- 简单变量目标在目标求值时只解析名字；不存在时在写入阶段才在当前作用域创建。因此 `a = a` 在 `a` 未绑定时是 R001，`a = 1/0` 失败后不会创建 `a`。
- 目标错误优先于 RHS：`a[99] = 1/0` 是 R003，`s[0] = 1/0` 是 R002，`*h = 1/0`（`h` 非 ref）是 R007，`p.z = 1/0`（2D）是 R003。目标错误发生后不求值 RHS。
- 待提交队列在离开赋值语句时统一提交，即使目标、RHS 或写入失败；已发生的副作用不回滚。
- `h = ref f` 是例外：按 §4.5 先校验 RHS，再解析/创建 LHS。`for` init 也是例外：按 §6.4 先在外层求 RHS，再新建循环变量。

```lush
i = 0
a = [10,20]
a[i] = i++          # a == [0, 20], i == 1

i = 0
a = [10,20]
a[i++] = i          # a == [0, 20], i == 1

i = 0
a = [10,20]
a[i++] = i++        # a == [0, 20], i == 2

i = 0
a = [10,20]
a[i++] = i++ + i    # a == [1, 20], i == 2

i = 0
a = [10,20]
a[++i] = i          # a == [10, 1], i == 1（目标里的前缀立即写回）

i = 0
a = [[0,0],[0,0]]
a[i++][i++] = i     # a[0][0] == 0, i == 2

i = 0
a = [10,20]
a[i++] = 1/0        # R004；i == 1，a 不变（目标后缀仍提交）
```

RHS 的后缀仍立即写回，因此 `i = i++` 最终仍是旧值，`i = i++ + 1` 最终是旧值加 1。这是 T 语义的直接结果；若希望整个赋值内的后缀统一在写入后提交，需要另一套快照语义，本版不采用。

### 6.2 if

`if (cond) stmt [else stmt]`：`cond` 必须 bool；`else` 绑定最近的未配对 `if`。

then 语句与 `else` 之间只允许换行，以及“终止 then 语句的那个 `;`”。额外的 `;` 是 `EmptyStmt`，会打断 `else` 的配对：

```lush
if (a) x = 1; else x = 2          # 合法：`;` 是 Assign 的终止符
if (a) x = 1
else x = 2                        # 合法：换行
if (a) x = 1;; else x = 2         # P001 在 else：第二个 `;` 是 EmptyStmt
if (a) x = 1
; else x = 2                      # P001 在 else：NL 已终止 Assign，分号是 EmptyStmt
if (a) {}
else x = 2                        # 合法：块以 `}` 结束
if (a) {}; else x = 2             # P001 在 else：`;` 是 EmptyStmt
if (a); else x = 2                # 合法：`;` 是 then 的 EmptyStmt
if (a);; else x = 2               # P001 在 else
```

`if (a) {} b = 2` 合法；`if (a) x = 1 c = 2` 报 P006 在 `c`。

### 6.3 while

`while (cond) stmt`：每轮重新求值 `cond`；`cond` 必须 bool。

### 6.4 for

**for-in：**

```lush
for i in expr stmt
```

- `expr` 在**外层作用域**求值一次，得到一个值（值语义，天然是快照），然后才创建循环变量；
- `expr` 之后允许换行（见 3.8）；
- 可迭代类型：list（逐元素）、string（逐码点）；Point 与其它类型 → R002；
- 每轮为 `i` 创建**新 cell**，元素拷贝进 `i`；
- `i` 在循环结束后不可见；
- body 可以是空语句 `;`；缺 body 且遇到 `}` 是 P001 在 `}`，在 EOF 是脚本 P002 / Repl `Incomplete(NeedStatement)`。

**C 风格：**

```lush
for (i = 0; i < n; i++) stmt
```

- init 槽只允许 `IDENT = expr` 或空；AST 中 init 表示为一个 `Assign` 节点（target 是 `Variable`），cond/step 分别是可空表达式；
- `for (p.x = 0; ...)` → P001 在 `.`；`for (i = ref j; ...)` → S004 在 `ref`；`for (i; ; )` → P001 在 `;`；
- step 只允许表达式，不允许赋值：`for (;; i = i + 1)` → P001 在 `=`；
- 有 init 时，先在**外层作用域**求值右侧，再在 for 作用域新建 `i` 并赋值（即使外层已有同名变量，也遮蔽）；init 不是普通赋值，不适用 §6.1 的 target-first；
- init、cond、step 都可以为空；cond 为空视为永远真；
- `i` 在整个循环期间是同一个 cell；
- `i` 在循环结束后不可见；init 为空时，cond/step 中引用的名字按普通作用域解析；
- 头部里的两个 `;` 不是 `EmptyStmt`；`for (;;);` 的第三个 `;` 才是 body 的 `EmptyStmt`；
- 缺 body 且遇到 `}` 是 P001 在 `}`；在 EOF 是脚本 P002 / Repl `Incomplete(NeedStatement)`。

### 6.5 break / continue

- `break` 跳出最内层循环；
- `continue` 进入最内层循环的下一轮；在 C 风格 `for` 中先执行 step 子句，再判断 cond；
- 不在循环内 → S005。

### 6.6 块

`{ ... }` 是语句，引入新作用域。块可以单独出现。

### 6.7 命令语句

`IDENT word*`：

- 名称按大小写不敏感查找注册表；
- 参数按 3.4 切词并求值，从左到右；
- 再按参数的声明类型做绑定转换（7.2）；
- 函数有返回值（作为语句调用时丢弃）；函数名在表达式位置是 callable 值；
- 未注册的名字 → S001；
- 参数个数不符 → S002；交互命令缺参且不满足会话条件 → S006；
- 命令不能出现在表达式位置 → S008。

### 6.8 函数体与 return

- 用户函数的 body 可以是 block 或单条语句；两种形式都引入函数调用作用域。
- 函数参数在进入函数时创建为局部 cell；参数名在函数体内优先于同名全局变量。
- 函数体执行到 `return expr` 时，按 `-> type` 做返回值绑定；只有 int → double 的提升允许。
- `return;` 结束 void 函数；void 函数自然结束时也正常返回。
- 值函数执行到 body 末尾仍未执行 `return expr` 时，报 R014；不会隐式返回 0、空字符串或最后一个表达式的值。
- `return` 穿过 `if` / `while` / `for` / block 传播到最近的函数调用边界；`break`/`continue` 仍只作用于循环。
- 函数调用递归深度由运行时计数器限制为 1024；超过报 R015。深度按用户函数调用计，不按宿主 callable 计。
- 函数体中的命令、表达式、`echo` 和宿主函数使用当前 `Output`/Registry；宿主失败仍按 R010 处理。

## 7. 命令系统

### 7.1 注册表

```text
CommandSpec {
    name        : string          // 规范拼写，大小写不敏感唯一
    aliases     : [string]
    params      : [ParamSpec]     // 顺序即位置参数顺序
    returns     : void | value
    returnType  : ReturnType?     // 仅 value；缺省 = unknown；void 必须省略
    interactive : bool            // 仅 void 命令可为 true
    help        : string
}

ParamSpec {
    name        : string
    type        : int | number | point | string | bool | list | any
    dim         : 0 | 2 | 3       // 仅 point 有意义，0 = 不限
    optional    : bool
    default     : 字面量          // optional 时必填
    variadic    : bool
    hint        : string          // 交互提示与补全说明
}

ReturnType {
    type        : int | double | bool | string | list | point | callable
    dim         : 0 | 2 | 3       // 仅 point 有意义，0 = 未知/不限
}
```

`Signature` 保留注册后解析出的同一个可选 `returnType`；它不改变 §7.2 的动态参数绑定，也不改变命令/函数的运行时值。

注册约束：

- 名称与别名不得是关键字；
- 名称与别名大小写不敏感唯一，且不得与内建函数、`echo` 或其他已注册名称冲突；
- 必选参数必须排在可选参数之前；
- 变参必须是最后一个参数，且变参命令不能有任何可选参数；变参参数自身必须 `optional = false`，且不能有 `default`；
- 只有可选参数可以有 `default`；必选参数和变参参数不得有 `default`；
- 默认值只接受字面量：int、double、bool、string、list、Point。callable 不是字面量，不能作为默认值；默认值在注册时按 §7.2 绑定到参数类型（如 `number` 的 int 默认值提升为 double，`point` 的 list 默认值转换为 Point），无法绑定的默认值是注册错误；
- `returns = void` 时必须省略 `returnType`；`returns = value` 时 `returnType` 可选，缺省表示宿主未声明返回类型；
- `returnType.dim` 只对 `point` 有意义；非 point 必须为 0，point 只允许 0/2/3；
- `returnType` 只用于补全和静态推断，**不是运行时契约**；宿主函数实际返回其它类型时不产生新的运行时错误；
- 注册失败（名称/别名冲突、关键字、参数顺序、变参/默认值非法、void 带返回类型、非法返回维度等）是宿主编程错误，不产生 L/P/S/R 诊断；
- 注册应在执行脚本/开始会话之前完成；脚本内不能注册。
- `returns = value` 的可调用体有值形态（callable）；`returns = void` 的命令只能作为语句，没有值形态。

### 7.2 参数绑定与转换

| 声明类型 | 接受的值 | 绑定结果 |
|---|---|---|
| `int` | int | int |
| `number` | int / double | double（int 提升） |
| `point` | point（维度需满足 `dim`） | point |
| `point` | list（长度 2/3、元素数值） | point（坐标转 double） |
| `string` | string | string |
| `bool` | bool | bool |
| `list` | list | list |
| `any` | 除 void/ref 外任意（含 callable） | 原值 |

其余情况 → R002（带参数名与期望类型）。

`point` 参数收到 list 时执行 §4.6 的 `list → point` 转换：长度或元素不合法 → **R006**（位置在该参数）；收到非 point/list 类型、或 point 维度不满足 `dim` → **R002**（位置在该参数）。

参数求值与绑定顺序：

- 一次命令/函数调用中，所有参数表达式按源码从左到右求值，全部求值完成后才按 `ParamSpec` 绑定/转换；
- 因此绑定错误（R002/R006）发生在参数求值之后，后续参数的副作用可能已经发生；
- 交互式会话按输入逐个补齐参数，每个输入求值并绑定后才提示下一个；一次性给出的完整命令仍遵循“先全部求值，再统一绑定”。

### 7.3 元数与变参

- 必选参数个数 `R`，固定参数总数 `N`（不含变参）；
- `argc < R` → 参数不足（是否进入会话见 7.4）；
- `argc > N`（非变参）→ 参数过多；
- 变参命令不得有可选参数（§7.1），因此变参命令的 `R == N`；变参槽位不计入 `R`/`N`；
- 变参吞掉剩余全部参数，逐个按变参类型绑定；变参可以接收 0 个参数，不需要 `optional`；
- 可选参数缺省时使用 `default`；默认值已在注册时绑定。

### 7.4 交互式会话

只有满足以下全部条件时，参数不足才进入会话：

1. 当前处于**行模式（REPL）**，而非脚本模式；
2. 本次输入在**顶层**；
3. 整个输入恰好是**一条命令语句**（允许结尾空语句/注释）；
4. 该命令 `interactive == true`。

**参数不足**在这里指 `argc < required`（§7.3）。`argc >= required` 时不进入会话，缺省的可选参数直接使用 `default`。`hint [default]` 的可选参数提示属于补全/Tooltip，不是会话行为。

参数不足时：

- 满足上述全部条件 → 进入会话；
- 否则，交互命令 → S006；
- 非交互命令 → S002。

任何命令参数过多 → S002。

会话返回四种状态（REPL 语法未完成的 `NeedMore` 是驱动层状态，不属于会话状态）：

```text
DONE | NEED_INPUT(prompt, type, dim, index) | ERROR(diagnostic) | CANCELLED
```

`NEED_INPUT` 的 `index` 从 0 开始，`prompt` 取 `hint`，缺省用参数名。

会话行为：

- 会话启动前已提供的参数按 §7.2 先全部求值，再统一绑定；会话中每次输入只求值并绑定当前必选参数；
- 会话只收集必选参数。必选参数全部绑定后立即执行命令，剩余可选参数取 `default`，不提示可选参数；
- 对第一个缺失的必选参数返回 `NEED_INPUT`，携带 `prompt`、期望类型、维度和参数序号；
- 会话模式下，后续每一行输入按 `barePoint | expr` 解析（与命令参数同一规则），例如 Point 参数可直接输入 `0,0`；当前一次一行，不支持会话内多行表达式；
- 会话输入中的纯注释行忽略并继续当前参数；空白行按空输入处理；
- 表达式错误只报错并停留在当前参数，不结束会话；
- 空输入：会话中的当前参数必为必选参数，取消会话（R011）；
- 宿主可随时 `cancel()`；取消不调用命令；
- 宿主的鼠标点选可以直接提交一个 Point，不必经过文本解析；绑定失败没有文本 Span，错误码仍为 R002/R006，并以 DirectPoint 标记输入来源；
- interactive 变参命令只补必选固定参数；变参不参与会话补齐，可以为 0 个；
- 全部参数绑定后调用命令，返回 `DONE`；
- 命令的副作用由宿主负责，核心不做回滚。

示例：

```text
> line
指定第一个点: 0,0
指定第二个点: 1,1
LINE (0, 0) (1, 1)
```

### 7.5 与变量命名空间

命令、内建函数和用户函数共用一张 callable 命名空间；变量存放在独立的作用域链中。语法位置决定调用写法：

- 语句位置：`name arg arg ...` 解析为可调用体，返回值（若有）丢弃；
- 表达式位置：`name(...)` 是调用；裸 `name` 若是函数名则是 callable 值，若是命令名 → S008，否则是变量；
- 用户函数名大小写不敏感，像命令/内建一样参与语句位置查找；顶层 `def` 在程序开始前收集并提升；
- 变量名不得与已注册名称或用户函数名冲突（S003/S011；具体见 §2.5 的写入/绑定目标规则）；
- 类型构造器、内建函数和用户函数是一等值，可存入变量/list，可作为参数传递；
- 变量中保存的 callable 不是命令：语句位置 `t 1` 仍按命名空间查找，找不到报 S001；只能用表达式位置 `t(1)` 调用；
- 用户函数的语句位置并置调用写作 `f 1 2`；`f(1,2)` 在语句位置仍按命令 + 一个 Point 参数解析。void 函数只能作语句调用，不能用于表达式。
- 用户函数的语句位置 arity 错误按 S002（命令名），表达式位置调用 arity/类型错误按 R002（`(` / 违规参数）；参数绑定规则见 §3.10，不复用命令的 list → point 转换。

### 7.6 参考宿主（测试 / CLI 演示）

规范定义以下可调用体，作为 golden tests 的基准；真实宿主可自由替换。M5 的 CLI 使用该参考宿主作为演示宿主。`line`、`circle`、`move` 不属于语言核心，核心只内置 `echo`。

| 名称 | 类型 | 交互 | 签名 | 输出 |
|---|---|---|---|---|
| `line` | 命令 | 是 | (p1: point dim2, p2: point dim2) | `LINE <p1> <p2>` |
| `circle` | 命令 | 是 | (c: point dim2, r: number) | `CIRCLE <c> <r>` |
| `move` | 命令 | 否 | (dx: number, dy: number) | `MOVE <dx> <dy>` |
| `echo` | 命令 | 否 | (v: any ...) | 值以单空格连接后换行 |
| `read` | 函数 | 否 | (prompt: string = "") -> string | 输出 prompt 后读取一行 |

交互提示：

- `line.p1` = `指定第一个点`，`line.p2` = `指定第二个点`
- `circle.c` = `指定圆心`，`circle.r` = `指定半径`

命令执行失败由宿主返回 R010；失败前的输出保留，Span 默认按 §11.3。

`read` 是参考宿主专有的宿主函数，不是语言核心内建；真实宿主可以不提供它。

- `read()` 不输出提示；`read("提示: ")` 先通过宿主 Output 写出提示，再读取一行；
- 返回内容不包含换行；Windows 风格输入的尾随 `\r` 会被去掉；空行合法，返回空字符串；
- 读取失败、EOF 或输入不是有效 UTF-8 → R010；
- 它是 value 函数，不是 interactive 命令，可以出现在表达式位置；语句位置调用会读取并丢弃结果；
- 它直接使用宿主的输入流，不经过 Driver 的 pending、会话、SourceId、Ctrl+C 或 R011 状态机；
- v1 不引入统一的 HostInputService；宿主应显式注入输入流和 Output，或在没有输入源时让 `read` 返回 R010；
- 宿主 value 函数不要求是纯函数；`FunctionHandler` 仍不接收 `Output` 参数，`read` 通过 ReferenceHost 捕获的 Output 输出提示。

## 8. 内建

### 8.1 函数（一等 callable）

以下都是 callable 值，可以存进变量/list、作为参数传递；它们的类型都是 `type`。

| 名称 | 签名 | 说明 |
|---|---|---|
| `int` | `(int\|double\|string)` | double 向零截断；string 按严格十进制整数解析；越界 R005，格式非法 R013 |
| `double` | `(int\|double\|string)` | int 提升（可能丢精度）；string 按 Lush 数值语法解析；格式/范围非法 R013 |
| `bool` | `(bool\|int\|double\|string\|list)` | 显式真值转换：`0`/`0.0`/`""`/`[]` → false；非空 → true；Point → R002 |
| `string` | `(any)` | 按第 9 节格式化为 string；`str` 是同一 callable 的别名 |
| `list` | `(list\|string\|point)` | list 深拷贝；string 逐码点；point 取坐标；其它 R002 |
| `point` | `(v)` / `(x,y)` / `(x,y,z)` | 由 list/Point 复制，或由数值构造 |
| `type` | `(any)` | 返回该值的类型构造器；callable → `type` |
| `len` | `(list\|string\|point)` | list 长度、string 码点数、point 维度 |

用于补全的静态返回类型：`int` → int，`double` → double，`bool` → bool，`string`/`str` → string，`list` → list，`point` → point（维度未知），`type` → callable，`len` → int；`echo` 是 void 命令。这些返回类型是静态元数据，不改变本表的运行时语义。

数值字符串转换规则（`int(string)` / `double(string)`）：

- 只做显式转换；不允许隐式把 string 用作数字。
- 两端允许 ASCII 空格、水平制表符和 `\r`，内部不允许空白；空串或纯空白 → R013。
- `int` 只接受可选 `+`/`-` 加一个或多个十进制数字；不接受小数点、指数、下划线、十六进制。
- `double` 接受与 §2.6 字面量相同的数值语法：整数部分为十进制数字，可带小数部分和指数；不接受 `1.`、`.5`、`nan`、`inf`。
- `int` 的数值超出 int64 → R005；其它格式或越界情况 → R013。`double` 的越界、下溢或非有限结果 → R013。
- 使用 locale 无关的解析；不接受 locale 小数分隔符。

表达式位置的 callable 参数个数错误 → **R002**（位置在调用 `(`）；参数类型错误 → **R002**（位置在违规参数）。语句位置的可调用体按命令参数规则报 S002（位置在命令名）。

语句位置的 builtin 函数调用同样合法，返回值丢弃：`int 1`、`point 1 2`、`len [1,2]` 都是合法语句；`int 1 2` 是 S002（位置在命令名）。`echo` 是命令而不是 value 函数，仍只能作为语句。

`type` 的返回值就是对应的 callable 本身：

```lush
type(4.4) == double      # true
type(4.4)(2)             # 2.0
type(1) == int           # true
type("a") == string      # true
type(true) == bool       # true
type([1]) == list        # true
type((1,2)) == point     # true
type(len) == type        # true
type(type) == type       # true
```

`bool(v)` 是**显式转换**，不改变 4.8 的规则：`if (0)` 仍然 R002，必须写 `if (bool(0))`。

`point(v)` 中 `v` 为 list 时执行 4.6 的 `list → point` 转换：长度或元素不合法 → R006；`v` 为 Point 时复制；其它类型 → R002。`point(x,y[,z])` 的数值参数必须是 int/double，否则 R002；参数个数错误 → R002（位置在调用 `(`）。

`str(v)` 与 `string(v)` 是同一个 callable；规范名是 `string`，`str` 仅作为别名保留；格式化 callable 时输出规范名 `string`。

## 9. 格式化

`string(v)`（别名 `str(v)`）与 `echo` 使用同一套格式：

| 类型 | 格式 | 示例 |
|---|---|---|
| int | 十进制 | `42` |
| double | 最短可往返表示；整值不带 `.0` | `0.5`、`1`、`1e+20` |
| bool | `true` / `false` | `true` |
| string | 顶层原样；嵌套加引号并转义 | `abc`、`["a", "b"]` |
| point | `(x, y)` 或 `(x, y, z)` | `(1, 2)` |
| list | `[a, b, c]`，空为 `[]` | `[1, [2, 3]]` |
| callable（`type` 值） | callable 的名字 | `int`、`double`、`len` |

- double 使用最短可往返表示；科学计数法统一为 `e` + 符号 + 十进制数字，指数不补前导零（`1e+20`、`1e-7`）；
- `echo a b c` 输出 `a b c\n`；
- `echo` 对 string 参数输出原文（不含引号）；
- list/Point 内部的 string 加双引号，并转义 `\`、`"`、换行、制表符与控制字符；
- `-0.0` 输出 `0`；
- 不存在 NaN/Inf，因此无需特殊格式。

## 10. 执行模型

### 10.1 脚本模式

1. 词法 + 语法 + 校验整个程序；
2. 任一阶段出错 → 不执行任何语句，返回第一个错误；
3. 校验通过后收集全部顶层 `def`，安装函数值并提升到 callable 命名空间；函数体延迟到调用时执行；
4. 顺序执行语句；
5. 运行时错误（包括宿主命令失败 R010）立即中止，已产生的输出与命令副作用保留；
6. EOF 时仍有未闭合的 `{`/`(`/`[` → P002。

脚本模式**不进入交互会话**：交互命令参数不足一律 S006；非交互命令参数不足、以及任何命令参数过多一律 S002。

校验阶段检查：未知命令、参数个数、保留名写入/绑定、`break/continue` 位置、交互命令是否顶层单条、顶层 `def` 位置/重名/参数名/类型注解、函数调用返回值形态、`return` 位置与返回类型。Parser 仍提前报告 S004/S009；`return` 在函数外由校验阶段报 S010。

### 10.2 行模式 / REPL

- Env 跨行保留；顶层用户函数定义也跨行保留，函数值拥有函数体 AST 和 Source 句柄。
- 解析器在 Repl 模式下返回 `Incomplete`，原因与优先级为：
  1. 已经出现的确定性错误（不是“输入末尾缺少 token”的 P001/P003/P005/S004/S009/L004 等）优先，直接返回 `Error`；`a = ref` 这种仅因 RHS 在末尾缺失而产生的 S004 可被尾随续行 defer；
  2. `Unclosed*`：输入末尾仍有未闭合的 `{`/`(`/`[`；多个未闭合时取**最内层**的类型；
  3. `NeedStatement`：`if` / `while` / `for` / `for-in` / `else` 的控制头已经完整，但缺少 body；
  4. `TrailingContinuation`：最后一个被删除的合法续行之后没有产生任何**非 NL** token；注释、空白行、注释行产生的 NL 都不算。包括 `\` 位于 EOF（L005）、`\` 后只有水平空白/注释/空行，或最后一行以 `\` 后跟零个或多个水平空白结束；
  5. 以上都不是时，按普通结束错误处理：缺少表达式是 P002（位置在显式语句终止符或 EOF）；`a = ref` 缺少 RHS 仍是 S004。显式终止符上的 P002/S004 只有在没有尾随续行时才会走到这里。
- `endsWithContinuation` 由 Lexer 提供：最后一个合法续行之后没有非 NL token 时为 true；L005 也置 true。LexResult 同时提供 `lastContinuationOffset`（最后一个被删除合法续行的原始 offset；L005 是反斜杠 offset；没有则为 npos）。
- 是否把 P002 转成 Trailing 还要看错误位置：只有终止符/EOF 位于最后一个续行之后（或错误是 `a = ref` 的 RHS 在末尾缺失）才 defer。显式终止符在续行之前时仍是确定错误，例如 `a = 1 + ; \` 是 P002 在 `;`，不是 Incomplete。
- REPL 以 `... ` 继续读取，直到完整、用户取消，或按空白行取消待完成输入。
- 完整后按累积缓冲区解析并执行；满足 7.4 条件时进入会话。
- 出错返回提示符，Env 不变（已发生的副作用不回滚）。

**空白行策略**

- 当前是 `NeedStatement` 或 `TrailingContinuation`：空白行**取消**待完成输入，不执行、不报错，回到普通提示符。
- 当前是 `UnclosedBrace` / `UnclosedParen` / `UnclosedBracket`：空白行是合法空白，追加到缓冲区，继续等待。
- 只有注释的行不算空白行；它被追加，并继续保持当前 `Incomplete` 状态。
- 顶层没有待完成输入时，空行是空语句。
- 空 body 必须显式写 `;`：`if (a);`、`while (a);`、`for (;;);` 合法；`for (;;);` 执行时会死循环，但这是用户显式写的。

**REPL 结束与取消**

- 普通状态遇到 EOF：结束 REPL。
- 有待完成输入时遇到 EOF：按 `ParseOptions::Script` 重新解析当前 buffer；有诊断则报告该诊断；若 Script 解析成功，则合成 P002 在 EOF。
- 会话中遇到 EOF：取消会话，不执行命令，不产生 R011。
- Ctrl+C 由 CLI 解释为取消：会话中取消会话，待完成输入中取消 pending，空闲时清除当前行并重新显示提示符；不产生 R011。脚本模式不特殊处理。
- 会话必选参数收到空输入：取消会话并产生 R011，见 §11.3。

**不算 `Incomplete` 的情况**

- `a = 1 +`、`a =` 后接显式语句终止符（NL / `;` / `}` / `else`）或 EOF 是 P002；如果末尾存在尾随续行，则按 `Incomplete(TrailingContinuation)`。
- `a = ref`、`a = ref` 后用普通换行接变量，都是 S004，不是 `Incomplete`。
- Repl 中 `a = ref \` 以显式续行结尾、且后面没有非 NL token 时返回 `Incomplete(TrailingContinuation)`；`a = ref 1 \`、`a = ref f + \`、`a = ref ; \` 仍然是 S004（`;` 已终止语句，不能靠续行补救）。
- `a = ref \` 后接注释行再 EOF 返回 `Incomplete`；如果注释行之后还有非 NL token（例如 `f`），注释行的 NL 终止逻辑行，按普通规则报 S004。
- `if (a) else ...` 在 then body 位置遇到 `else`，是 P001，不是 `Incomplete`。
- 未闭合字符串是 L002，不是 `Incomplete`。

例如 Repl 中 `if (true)` 后 EOF、`for (;;)` 后 EOF 返回 `Incomplete(NeedStatement)`；脚本中两者都是 P002。

脚本模式不续行：未闭合括号在 EOF 上是 P002；`\` 位于 EOF（没有换行）按 2.3 报 L005；`\` + 换行仍是合法续行；控制头缺 body 是 P002。脚本中 `a = 1 \` + 换行 + EOF 合法；`a = 1 + \` + 换行 + EOF 是 P002；`a = ref \` + 换行 + EOF 是 S004。`a = 1 + \` + 换行 + 注释行 + 换行 + `2` 时，注释行的换行终止表达式，P002 在该 NL，`2` 视为下一条语句。

### 10.3 错误策略

| 阶段 | 策略 |
|---|---|
| 词法/语法/校验 | 首错中止，整段不执行 |
| 运行时 | 首错中止当前执行 |
| 会话 | 表达式错误停留当前参数；取消结束会话 |

词法整体成功后才进入语法/校验。词法阶段内部按源文本位置报告第一个错误：非法 UTF-8 按其第一个非法字节的位置参与排序，不会无条件覆盖更早的词法错误。

语法层（M2 Parser）可以提前报告 S004（非法 `ref`）、S009（`++`/`--` 目标不可赋值，位置在运算符）；紧贴 `.` 后的成员名位置例外，按 P004 处理。这些错误仍按源文本位置参与首错排序，不改变“语法/校验首错中止”的策略。`Error`/`Incomplete` 都不返回部分 AST。

阶段优先级固定为：词法 → 语法（含 Parser 提前报告的 S004/S009）→ 校验。前一阶段出现错误时不进入后一阶段；同一阶段内按源文本位置取首错。因此后面的语法错误会先于前面的校验错误报告。

### 11.2 格式

```text

  --> 3:6
   |

   = help: 运算符必须紧贴左操作数，或把整个表达式括起来
```

| R014 值函数缺少返回值 | 函数体结束位置（body 闭括号或单语句结束位置） |
| R015 递归过深 | 触发超限的用户函数调用 callee |

宿主通过鼠标直接提交 Point 时没有文本输入；Point 绑定失败的错误码仍为 R002/R006，Span 为空，并由宿主以 DirectPoint 标记输入来源，不要求伪造 Source。

对没有自然 token 的合成位置（如 callable 的 arity）使用调用左括号。Parser 的 P 错误位置继续按 §3.9。

## 12. 补全契约

补全引擎必须复用同一套词法与切词规则，禁止另写一套扫描器。补全是纯计算：不执行表达式、不调用宿主、不写输出、不产生诊断。

### 12.1 输入、光标与替换

- 输入是当前完整缓冲区、原始文本字节偏移 `cursor`、当前 `Env`、当前可调用体注册表和可选的会话 `NeedInput`；REPL 的 pending 文本由调用方拼接。
- 只分析 `[0, cursor)`；cursor 超出范围、位于字符串/注释/数字字面量中、或前缀存在词法错误时，返回空候选，不产生诊断。
- cursor 紧接 Identifier 时，用 token 起点到 cursor 的文本做前缀匹配，并替换整个当前 token；cursor 在空白、分隔符或运算符后时，替换空 span。
- cursor 紧接一个已完成的表达式且没有空白时，不做命令参数补全，避免替换已输入的表达式。
- 候选携带：插入文本、标签、来源（keyword/command/function/type/variable/member/literal/syntax）、类型/维度、签名或详情、`hint`、可选默认值、`typeMismatch` 和替换 Span。
- 补全不改变语义，也不执行宿主或会话。

### 12.2 上下文

| 光标位置 | 上下文 |
|---|---|
| 语句开头，或换行 / `;` / `{` / `}` / `else` 之后 | 语句开头 |
| `=`、运算符、`if (`、`while (`、`for (`、`?`、`:` 等之后 | 表达式 |
| 顶层语句位置命令名之后、且已出现空白 | 命令参数第 k 个 |
| `for <IDENT> in ` 之后 | 可迭代表达式 |
| `[` 或 `[expr,` 内 | 表达式 |
| `(` 内（Point/分组） | 表达式 |
| 表达式位置 `IDENT` 紧贴 `(` | 该 callable 的参数 |
| `.` 之后 | 成员 |
| 会话缺少必选参数 | 当前会话参数 |

补充规则：

- 只有表达式位置的紧贴 `IDENT(` 是 callable 调用；`line(` 是语句位置命令 `line` 的第一个 Point/表达式参数，不是函数调用。
- `for i in` 识别为可迭代上下文；`for (` 的 C 风格头仍按表达式处理。
- 块内、`{` 后、`;` 后都按语句开头处理；`{}` 不抑制换行，符合 §3 的终止符规则。
- `.` 的 receiver 只做静态类型推断，不执行任何表达式或副作用。

### 12.3 候选与匹配

候选来源：

- 关键字；
- 当前 `Env` 的可见变量；
- 已注册命令和函数；
- 类型构造器；
- 字面量模板；
- 成员；
- 会话当前参数。

关键字按上下文提供：语句开头提供 `if` / `while` / `for` / `break` / `continue` / `def`，`else` 仅在 `}` 后，`in` 仅在 `for <IDENT>` 后，`return` 仅在函数体内；表达式提供 `true` / `false`。用户函数候选来自当前 callable 命名空间和 `Env` 中的函数值；签名包含参数名/类型/必选性和返回类型。

字面量模板：

- 未指定类型的表达式：`true`、`false`；
- `int` 参数：`0`；
- `number` 参数：`0`、`0.0`；
- `bool` 参数：`true`、`false`；
- `string` 参数：`""`；
- `list` 参数：`[]`；
- `point` 参数：`(`；
- `any` 参数不额外提供字面量模板；
- 可迭代上下文提供 `[]` 和 `""`，以及已知 list/string 变量。

匹配与类型：

- 关键字、命令/函数/类型构造器名、别名：大小写不敏感前缀匹配；
- 变量：大小写敏感前缀匹配；成员：大小写敏感前缀匹配；
- 命令参数按 §7.2 的类型/维度过滤：`int` → int；`number` → int/double；`point` → 维度匹配的 point 或可转换的 list；`string`/`bool`/`list` → 对应值；`any` → 所有变量，并额外列出 callable；
- 用户函数参数按 §3.10 过滤：`int` → int；`double` → int/double；`point2`/`point3` → 对应维度的 point，不接受 list；`any` → 所有变量，并额外列出 callable；`callable` → callable 变量；
- 类型不匹配的变量仍显示，但标记 `typeMismatch` 并排在兼容项之后，附类型标签；
- 补全不得改变语义：在 `line 1,2 ` 处应建议 Point 类型变量与 `(`，而不是数字。

插入与详情：

- 核心候选默认只插入纯文本名字；Point 类型上下文额外提供显式 `(` 语法项；不自动附加空格或 `(`。
- 命令/函数/类型构造器的详情包含签名和帮助；命令参数的详情包含 `hint`；可选参数的详情可显示 `hint [default]`；会话参数的详情使用 `NeedInput.prompt`。
- 兼容项优先，类型不匹配项最后；同组按稳定的标签顺序排列。
- 别名作为独立候选参与匹配和插入；规范名候选仍保留。

### 12.4 成员与调用

- `point` 已知 `dim2` → `x`/`y`，`dim3` → `x`/`y`/`z`；维度未知 → `x`/`y`/`z`，z 的运行时合法性仍按 §4。
- `list` / `string` → `length`；callable、未知类型和其它值 → 无成员。
- `f(` / `t(` 内按该 callable 的声明参数类型提供候选；已注册函数使用 `Signature.params`，内建使用 §8 的静态签名，用户函数使用 `def` 的参数注解；类型未知时不额外过滤。
- 调用的静态类型来自 `Signature.returnType`（已注册/内建）或用户函数的 `-> type`；未知返回类型不影响补全本身，但不提供基于返回类型的成员或可迭代候选。
- 用户函数的 `void` 返回不提供成员候选；void 函数也不应出现在要求值的位置。
- 用户函数在语句位置也有候选；其插入仍是纯文本名字，不自动补 `(` 或空格。

### 12.5 会话补全

- 当前缺少必选参数时使用 `NeedInput.type`、`dim`、`prompt`；
- 候选规则与命令参数一致；
- Point 会话输入仍提供 Point 变量和 `(`，不把数字字面量当作默认候选；
- 可选参数不进入会话补全；会话内仍只接受单行 `barePoint | expr`。

### 12.6 无候选与边界

- 无候选时返回空列表，不返回诊断，不改变 Source/Env/会话状态。
- 不在字符串、注释或数字字面量内部补全。
- CLI 的 Tab 补全在 M9 接入；使用 vendored replxx，核心补全 API 与测试继续独立。M10 的编辑器分析接口另行定义 trivia、未完成 token 和错误 span，不复用严格执行的诊断路径。

---

## 13. 保留与未实现

- `def` / `return` 在 0.4.0 起启用；S007 废弃。
- 用户函数第一版限制：只允许顶层定义；无闭包、无嵌套 `def`、无默认参数、无变参参数；无用户自定义类型。
- 未来扩展方向：闭包、模块、异常、插件注册、写时复制、编辑器增量分析、错误恢复。
- 明确不加：`as` 后缀转换、隐式数值/字符串转换、多行字符串、块注释。
- 编辑器分析接口（M10）与 CLI Tab（M9）不是执行路径语义；它们只在宿主/CLI 适配层消费 token/trivia/span。

---

## 14. 图灵完备性

语言具备无界循环（`while`、`for`）、可变状态（变量、list、Point 分量）、条件分支，足以表达任意可计算过程；实际受 int64 与内存限制。

注意：int64 是有限精度，因此严格意义上不是无界整数模型。若未来需要真正的无界整数，应新增 `bigint` 类型而不是改变 `int` 语义。

## 16. EBNF 汇总

`NL` 为换行 token（受 2.2/2.3 抑制规则影响）。`word` 不是普通终结符，而是 3.4 切词后的 token 片段。

```ebnf
program     = { NL | ";" } { stmt ( NL | ";" | &EOF ) } EOF ;

stmt        = block
            | ifStmt
            | whileStmt
            | forStmt
            | breakStmt
            | continueStmt
            | defStmt
            | returnStmt
            | refAssign
            | assignStmt
            | commandStmt ;

block       = "{" { NL | ";" } { stmt ( NL | ";" | &"}" ) } "}" ;
ifStmt      = "if" "(" expr ")" NL* stmt [ NL* "else" NL* stmt ] ;
whileStmt   = "while" "(" expr ")" NL* stmt ;
forStmt     = "for" IDENT "in" expr NL* stmt
            | "for" "(" [ IDENT "=" expr ] ";" [ expr ] ";" [ expr ] ")" NL* stmt ;
breakStmt   = "break" ;
continueStmt= "continue" ;
defStmt     = "def" IDENT "(" [ param { "," param } ] ")"
              [ "->" type ] ( block | stmt ) ;
param       = IDENT [ ":" type ] ;
type        = "int" | "double" | "bool" | "string" | "list"
            | "point" | "point2" | "point3"
            | "any" | "callable" | "void" ;
returnStmt  = "return" [ expr ] ;
refAssign   = IDENT "=" "ref" IDENT ;
assignStmt  = lvalue "=" expr ;
commandStmt = IDENT { word } ;

lvalue      = "*" IDENT
            | IDENT { "[" expr "]" | "." IDENT } ;   (* 后缀必须与前一项无空白 *)

word        = barePoint | expr ;                     (* 必须整词匹配 *)
barePoint   = simple ( "," simple ){1,2} ;           (* 2 或 3 个坐标 *)
simple      = "-"? atom suffix* ;
atom        = INT | FLOAT | IDENT | "(" expr ")" ;
suffix      = "[" expr "]" | "." IDENT | "(" [ expr { "," expr } ] ")" ;

expr        = ternary ;
ternary     = orExpr [ "?" expr ":" expr ] ;
orExpr      = andExpr { "||" andExpr } ;
andExpr     = eqExpr { "&&" eqExpr } ;
eqExpr      = relExpr { ( "==" | "!=" ) relExpr } ;
relExpr     = addExpr { ( "<" | "<=" | ">" | ">=" ) addExpr } ;
addExpr     = mulExpr { ( "+" | "-" ) mulExpr } ;
mulExpr     = unary { ( "*" | "/" | "%" ) unary } ;
unary       = ( "-" | "!" | "++" | "--" ) unary
            | "*" IDENT
            | postfix ;
postfix     = primary { "[" expr "]" | "." IDENT | "(" [ expr { "," expr } ] ")" | "++" | "--" } ;
primary     = INT | BOUNDARY_INT | FLOAT | STRING | "true" | "false"
            | IDENT
            | "(" expr ")"
            | "(" expr "," expr [ "," expr ] ")"
            | "[" [ expr { "," expr } ] "]" ;
```

补充约束（EBNF 无法直接表达）：

1. 关键字、命令名、函数/类型构造器名大小写不敏感；
2. `IDENT` 在语句位置是命令名；在表达式位置是变量，或已注册函数/类型构造器的 callable 值；命令名出现在表达式位置 → S008；
3. `lvalue` 的后缀必须与前一 token 紧邻；
4. **所有后缀运算符**（`[...]`、`.IDENT`、`(...)`、`++`、`--`）都必须紧贴左操作数；
5. 调用时 callee 必须是 callable，否则 R012；
6. `word` 必须恰好消费切词得到的全部 token；
7. 语句之间必须有一个终止符，紧邻 `}` 的语句除外；
8. 解引用 `*` 必须紧贴 `IDENT`：`*h` 合法，`* h` 是 P001；`*h[0]`、`*h.x`、`*h(1)`、`*h++` 都是 P001；
9. 前缀 `-`/`!`/`++`/`--` 不要求紧贴，后缀仍必须紧贴；
10. `ref` 与右侧 `IDENT` 必须在同一逻辑行；普通换行会终止语句并报 S004，显式 `\` 续行除外；Repl 的尾随续行可返回 `Incomplete`；
11. 空语句 `;` 可以作为控制语句 body；额外的 `;` 是 EmptyStmt，会打断 `else`；
12. 括号分组对可赋值性透明：`(x)++` 合法；
13. 语句位置只允许 block/if/while/for/break/continue/赋值/命令；单独的 `(`、`[`、字面量等是 P001；
14. 紧贴 `.` 后必须是 `IDENT`；否则 P004 在 `.`（`.` 后直接是终止符/EOF 时 P002）；
15. `BoundaryInt` 只在单目 `-` 的直接操作数中合法，其它位置 L004；`++`/`--` 的 S009 位置在运算符；
16. `defStmt` 只允许出现在程序顶层；嵌套 `def` 是 S011；顶层 `def` 在执行前收集并提升；
17. 参数类型注解省略 = `any`；返回类型注解省略 = `void`；`void` 不能作为参数类型；
18. `return` 只能出现在用户函数体内；`return expr` 只能出现在值函数，`return;` 只能出现在 void 函数；违反为 S010/S012；
19. 用户函数名、内建名和命令名共用 callable 命名空间，大小写不敏感；语句位置 `f 1 2` 是并置调用，表达式位置 `f(1,2)` 是后缀调用；
20. 用户函数参数不支持 list → point 隐式转换；返回只允许 int → double 提升。

## 17. 待定与后续

以下事项不影响 M8–M11 的主体实现，但需要后续拍板：

1. 用户函数是否在 0.5 引入闭包/嵌套 `def`；当前明确不提供。
2. 是否引入模块/import 与插件注册的生命周期。
3. 是否为 list 增加切片、拼接与内建函数。
4. 是否引入执行路径的错误恢复（一行错误不影响后续语句）；编辑器分析走独立的 best-effort 接口。
5. 是否在补全中引入 tree-sitter 之类的外部增量解析（当前不需要）。
6. 宿主编辑器分析的正式 API 形状（trivia、未完成 token、错误 span、UTF-8 位置映射）在 M10 定稿。
7. `replxx` 之外是否还需要 Windows 原生行编辑后端；当前只计划 vendored replxx。
